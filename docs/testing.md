# Tests and real-cluster smoke procedure

## Offline

Use the pinned Hermes source checkout at .upstream/hermes-agent-0.23.0 or set
HERMES_SOURCE to that unmodified checkout.

```sh
uv sync --frozen --extra dev
uv run --frozen ruff check src tests examples/openshift/render.py
uv run --frozen mypy --explicit-package-bases src/hermes_agent_sandbox
uv run --frozen pytest -q
uv build
```

PyCharm also has an Offline tests run configuration. If the IDE runner cannot start
with the selected interpreter, run the same suite through the IDE terminal.

Unit tests keep the existing claim/identity/error/discovery coverage. Loopback HTTP
tests use the actual installed SDK, including request headers, JSON decoding and
failure paths. tests/test_routed_runtime.py forwards those requests to the unmodified
official runtime and executes a real shell; it tests CWD, environment, payload stdin,
Hermes ShellFileOperations, nonzero exits and server deadlines. Linux is required for
native process-group timeout coverage. Windows can use an explicitly detected Git Bash
test shim; otherwise those tests skip. No test double is selectable as a plugin runtime.

The live read-only claim test remains off by default. It requires
AGENT_SANDBOX_LIVE_READ_ONLY=1, AGENT_SANDBOX_TEST_NAMESPACE=hermes-pilot-test-* and
AGENT_SANDBOX_TEST_CLAIM. It never creates/deletes resources.

## First real OpenShift test

For the opt-in built-image Docker test, see docs/docker-testing.md.

1. Build/publish the pinned runner image and install wheel 0.2.1 in your Hermes image.
2. Follow docs/openshift.md to discover actual selectors/ports and render, review and
   apply the test namespaces, RBAC, templates/pools and NetworkPolicies.
3. Mount the adapted two-profile policy read-only and enable the backend in each
   profile. Confirm actual Operator/router Deployment names and namespaces.
4. Run from the configured Hermes container, using its Python interpreter:

```sh
python -m hermes_agent_sandbox.smoke \
  --profile-home /var/lib/hermes/profiles/smoke-alpha \
  --profile-home /var/lib/hermes/profiles/smoke-beta \
  --operator-namespace YOUR_OPERATOR_NAMESPACE \
  --operator-deployment YOUR_RED_HAT_OPERATOR_DEPLOYMENT \
  --router-namespace agent-sandbox-system \
  --router-deployment sandbox-router-deployment \
  --allow-provision
```

The explicit flag permits normal claim and marker-file creation, restricted by the
smoke command to dedicated hermes-pilot-test-* namespaces. This command requires the
separate get-only smoke preflight Roles generated by render.py; ordinary execution
needs only claim get/create. No fake runtime/client is used.

It verifies Operator/router availability, pool/template access, router /healthz,
normal claim acquisition, echo/pwd/whoami/python, file creation and real Hermes
remote-file reads, CWD/export state, nonzero exit 23, command timeout 124, two profiles
with the same session ID receiving different sandboxes, no cross-profile marker
visibility, retained claim UID after cleanup, and a fresh provider reconnect reading
the retained marker. A failed check exits nonzero with FAIL; successful checks print PASS.

5. Confirm SUCCESS and inspect RETAINED_RESOURCES JSON. It records claim names,
   namespaces, UIDs, sandbox IDs and a unique marker ID. No resource is deleted, even
   when a later check fails.
6. Repeat after restarting the gateway to test process-restart persistence. Claims must
   have the same UIDs; marker files from the prior run should remain in the workspace.
7. Perform the positive/negative network checks in docs/openshift.md. Success of the
   execution smoke does not prove denial from unrelated workloads.
8. Review ownership and UIDs before approved cleanup:

```sh
oc -n hermes-pilot-test-alpha get sandboxclaim EXACT_PRINTED_CLAIM -o yaml
# Only after verifying UID, owner annotations and pool, and approving deletion:
oc -n hermes-pilot-test-alpha delete sandboxclaim EXACT_PRINTED_CLAIM
```

Repeat for beta, then remove unused pools/templates/test namespaces and explicitly
remove the pilot policies and smoke RoleBindings from shared namespaces. Deleting a
claim can cascade into workload/storage removal. No cluster-wide resource should be
removed by this procedure.

No OpenShift smoke or NetworkPolicy enforcement test has been run locally. The local
suite validates protocol and runtime behavior, not Red Hat image/SCC/CNI certification.
